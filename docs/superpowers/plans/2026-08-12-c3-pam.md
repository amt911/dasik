# C3 — PAM hardening: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `pam` block that locks an account out after repeated failures (surviving a reboot), caps runaway process counts, and enforces a password policy — without dasik becoming a thing that can lock you out of your own machine.

**Architecture:** One converging action, `PamAction`, owning three independent items in the `pam` domain: `faillock`, `limits`, `pwquality`. It follows `SystemdConfAction`'s shape — **write a drop-in, read the effective configuration** — and owns a whole file only where no drop-in mechanism exists. Every file involved is a pacman *backup* file, so ownership costs at most a `.pacnew`.

**Tech Stack:** Python ≥3.10, pydantic v2, pytest.

## Global Constraints

- `pam_faillock.so` is **already** in Arch's `/etc/pam.d/system-auth`, so faillock and limits touch nothing under `/etc/pam.d`.
- `pam_pwquality.so` is **not**, so pwquality must rewrite `/etc/pam.d/passwd` (a `shadow` backup file, 4 lines). Its blast radius is the `passwd` command, never login.
- `/etc/security/pwquality.conf.d/` and `/etc/security/limits.d/` are real drop-in directories; `/etc/security/faillock.conf` is not, so that one file is owned whole.
- Removal is gated on ownership: only an item a previous generation recorded is dasik's to undo.
- Defaults: `deny=5`, `fail_interval=900`, `unlock_time=600`, `persistent=true`. `limits` and `pwquality` stay off unless declared.
- `pam_faildelay` and `/etc/security/access.conf` are deliberately **out of scope**: faillock already stops brute force, and both can lock a user out of their own console.
- TDD; gates stay green; commit per task.

- [ ] **Step 2: run, watch fail.**
- [ ] **Step 3: implement.**

```python
_STOCK_PASSWD = (
    "#%PAM-1.0\n"
    "auth\t\tinclude\t\tsystem-auth\n"
    "account\t\tinclude\t\tsystem-auth\n"
    "password\tinclude\t\tsystem-auth\n"
)
```

The dasik version keeps the auth/account includes and replaces the password line, because that line is the whole point: `pam_unix.so use_authtok` is what makes pam_unix take the password pwquality already validated instead of asking for a new one.
