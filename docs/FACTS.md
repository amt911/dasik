# FACTS — verified facts an agent would otherwise re-derive

> **Convention** (see `AGENTS.md` § *Agent orchestration*): when you verify something against this
> repo or the running system that the next agent would otherwise have to look up again, append a
> one-line fact here — with **how** you verified it. Facts only, never plans or opinions.
>
> This is **not** the gotchas log. That one holds what is *not* deducible from the code and outlives
> the branch; this holds what is perfectly deducible and merely expensive to re-derive, and it may go
> stale and die with the branch.

> Format: `- `<name>` — <the fact, in one line>. *(verified: <how>, <YYYY-MM-DD>)*`

- `FACT-PR-2` — "Trusted" (i.e. locally signed via `pacman-key --lsign-key`) shows in `gpg --with-colons` two ways: the validity field (2nd column of `pub:`/`uid:`/`sub:`) flips from `-` to `f`, AND `--list-sigs` gains a `sig:` line from `Pacman Keyring Master Key <pacman@localhost>` whose sig-class field (11th column) carries a trailing `l` (`10l`) marking it LOCAL/non-exportable, versus the key's own self-signatures which are `13x`/`18x`. - `FACT-PR-3` — `arch-chroot` mounts a PRIVATE `/tmp`: a file created in the host's `/tmp` before chrooting (`probe-host`) is invisible inside `arch-chroot /mnt` (`ls: cannot access '/tmp/probe-host': No such file or directory`) because `findmnt -n /tmp` inside the chroot shows a fresh `tmp tmpfs rw,nosuid,nodev,inode64,huge=advise` mount; `/var/tmp` IS shared (a file placed there before chrooting, `amt911.gpg`, is visible inside) — so any temp file `PacmanRepositoriesAction.apply` writes for cross-context reuse (the downloaded key, the single-repo `pacman.conf`) must go under `/var/tmp`, never `/tmp`. *(verified: guest probe, 2026-09-16)*
